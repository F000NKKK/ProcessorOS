# ProcessorOS

Универсальная ОС для одноэтапных производственных машин Minecraft на CC: Tweaked. Один входной ресурс, одна физическая операция, выход готовой продукции. Тип механизма не зашит в код: пресс, пила, обдув и другие совместимые машины используют общий контроллер.

**Статус: экспериментальная разработка.** Проверка в реальной игровой фабрике ещё необходима.

## Установка

На новом компьютере CC: Tweaked:

```lua
wget run https://raw.githubusercontent.com/F000NKKK/ProcessorOS/master/install.lua
```

ОС запускается автоматически. При первом запуске выберите M (Master) или S (Slave) в терминале либо на мониторе. Роль сохраняется; изменить её можно только вручную в /processoros/data/config. Master работает без настройки машин.

На Slave остановите ОС через Ctrl+T, выполните /processoros/setup.lua и reboot. Мастер должен быть доступен по Ender Modem до начала настройки и при сохранении. Укажите имя группы, количество машин и четыре порта каждой. Master назначает постоянные глобальные номера по идентификатору компьютера и рабочим портам; повторная регистрация тех же портов сохраняет номера. Подача после настройки выключена. Включите её клавишей p или через монитор. Уже зарегистрированный Slave может работать при отключении Master. Существующие машины без глобальных номеров требуют повторной настройки после освобождения рабочих портов.

## Четыре обязательных порта

| Порт | Назначение |
|---|---|
| input | Исходные ресурсы |
| machine_input | Загрузка механизма |
| machine_output | Получение обработанного ресурса |
| output | Конечный инвентарь, например AE2 Pattern Provider |

Все порты должны иметь сетевые имена проводных инвентарей. Вход и выход могут быть общими для нескольких машин. Рабочие инвентари разных машин должны быть независимы. Для пресса machine_input и machine_output указывают на один Depot; для пилы с буферами — на два разных инвентаря. Поддержка конкретной физической схемы зависит от доступных периферийных API.

В одном рабочем инвентаре завершение определяется изменением ID/NBT. Используйте размер партии 1. В раздельных буферах готовый результат выгружается по мере появления; выход должен быть выделен исключительно под результат этой машины. Изначально рабочие буферы должны быть пустыми. AE2 самостоятельно планирует заказы; ОС не требует ME Bridge.

## Master / Slave

Монитор обнаруживается автоматически, включая подключение после запуска. Подключите его напрямую или через активированный проводной модем. Ender Modem используется только для связи компьютеров.  Для выбора конкретного монитора задайте monitor в /processoros/data/config.

Подключите компьютеры через Ender Modem. Проводная сеть нужна для локального доступа к инвентарям. Настройте одинаковую network_group. Master может управлять собственными машинами или быть отдельным монитором без машин. Slave продолжает обработку при отключении Master. Телеметрия передаётся раз в секунду; после пяти секунд без сообщений узел отображается OFFLINE. Сеть должна быть доверенной: группа не является аутентификацией. Удалённое управление и обновление пока не реализованы.

## Управление

Строка 2 монитора — START/PAUSE FEED, строка 3 — UPDATE OS (локальное обновление), последняя строка — страницы. Клавиши p/u/n/b дублируют эти действия. Обновление прекращает новую загрузку и ждёт освобождения наблюдаемых рабочих портов. Перед обновлением убедитесь, что механизм не удерживает невидимые для CC:T предметы. После обновления подача остаётся на паузе. Конфигурация и журнал сохраняются в /processoros/data.

## Безопасность

Не подключайте один рабочий инвентарь к двум контроллерам. Не сбрасывайте журнал при неопределённом перемещении: сначала проверьте физические ресурсы. При переходе со старой установки завершите её работу, опустошите рабочие механизмы и выполните настройку заново. Установщик сохраняет прежнюю автозагрузку и не удаляет пользовательские данные.

Многоингредиентные рецепты, жидкости и многоэтапные технологические маршруты не входят в базовую ОС.

## Регистрация с Master

Slave автоматически получает постоянное имя Slave NNN от Master и сохраняет его локально. Имя группы отдельно задаётся в настройках. Master назначает номера в постоянном реестре. На мониторе Master выберите узел строкой SELECT (левая/правая половина), затем REGISTER MACHINE. Slave ставит подачу на паузу; существующие рабочие порты должны быть пустыми и активных заданий не должно быть. Остановите физические механизмы, уберите посторонние маркеры. После приглашения положите ровно один булыжник в выбранный инвентарь, дождитесь обнаружения, затем уберите. Нажмите следующую строку порта; любую подтверждённую точку можно выбрать повторно. После четырёх точек нажмите SAVE MACHINE. Slave сохранит машину и перезагрузится, подача остаётся выключенной. CANCEL отменяет черновик. Для обнаружения маркера инвентарь должен отдавать list/pushItems через проводной модем и позволять ручную вставку/извлечение. Доверенная сеть Rednet обязательна. Экран регистрации требует не менее 16 строк.

## Локальный терминал

При первом запуске M/1 выбирает Master, S/2 — Slave. На Slave постоянно доступно терминальное меню независимо от наличия монитора. S запускает настройку после проверки связи с Master; G меняет имя группы; P управляет подачей; U обновляет ОС; Q останавливает контроллер и возвращает оболочку; H повторно выводит меню. Для изменения роли редактируйте конфигурационный файл вручную. Монитор рендерится отдельно и не очищает терминал. Настройка портов останавливает подачу и требует свободных рабочих инвентарей; после настройки перезапускается ОС.

Обновление из ОС не зависит от API shell: установщик загружается через HTTP и выполняется в текущем окружении. При ошибке загрузки подача остаётся на паузе.

Терминальные команды теперь вводятся строкой с Enter, например `s`, `g`, `p`, `u`, `q`, `h`. При первом запуске введите `1` или `2` и нажмите Enter. Фоновая телеметрия не пишет в строку ввода. `h` отображает актуальное имя Slave и связь с Master. `q` останавливает контроллер и возвращает стандартную оболочку CC:T.

## Master Dashboard

На большом мониторе доступна адаптивная сетка карточек машин, индикаторы активности, счётчики и кнопки регистрации, подачи и обновления выбранного Slave. Анимация показывает активность, а не проценты физической обработки. UPDATE SLAVE требует повторного нажатия; подтверждение ACK означает принятие команды, не окончание установки. Slave принимает команды только от сохранённого Master ID (доверенная сеть, не криптографическая аутентификация). Обновление ждёт освобождения наблюдаемых портов; вручную убедитесь, что скрытые внутренние буферы пусты. Подача после обновления остаётся выключенной.

Карточка машины открывается касанием заголовка. Детали показывают четыре порта, счётчик, скорость за последние десять секунд и историю до десяти минут (в памяти Master). EDIT PORTS открывает регистрацию с сохранением глобального номера. DELETE требует паузы подачи и пустых рабочих портов. UPDATE ALL SLAVES отправляет запрос всем видимым онлайн-узлам после повторного нажатия. ACK означает принятие, а не завершение обновления. Неопределённые перемещения всё ещё требуют ручной сверки.
