# SmelterOS

**SmelterOS** — контроллер печи Create Encased Fan (обдув через лаву) на компьютере CC: Tweaked. Управляет загрузкой с Functional Storage Oak Drawer на Create Depot, следит за изменением **ID/NBT** предмета и возвращает результат в AE2 Pattern Provider (или другой инвентарь). Интерфейс рассчитан на **горизонтальный монитор 4 × 2 блока** с масштабом текста `0.5` и автоматически подстраивается под реальный размер в символах.

> **Статус:** v0.1.0 — первая экспериментальная версия. Аппаратная конфигурация конкретной сборки **не протестирована в игре**. Первая загрузка безопасна: автоматика **выключена** до нажатия START FEED.

## Установка одной командой

Вставь в терминал компьютера CC: Tweaked:

```lua
wget run https://raw.githubusercontent.com/F000NKKK/SmelterOS/master/install.lua
```

Требуется разрешённый HTTP API сервера. Установщик скачивает файлы в `/smelteros`, сохраняет пользовательские `/smelteros/data/config` и `/smelteros/data/state` при обновлении, резервирует ранее существовавший `/startup.lua` в `/smelteros/previous_startup.lua` и перезагружает компьютер. После каждой перезагрузки CC:T автоматически запускает `/startup.lua`.

Для обновления запусти **ту же команду**. Отдельное копирование файлов не нужно.

## Подключение

1. Прикрепи проводной модем к **каждому** инвентарю (депо, ящику, AE2 Pattern Provider), подключи модемы к одной проводной сети и **активируй каждый модем правой кнопкой**. Компьютер тоже должен быть в сети. В некоторых конфигурациях `inventory.pushItems()` не работает для инвентаря, подключенного только как соседний `left`/`back`; нужна проводная сеть.
2. Поставь 4×2 продвинутых монитора единым экраном и подключи к компьютеру. Это **один** периферийный `monitor`. Можно прикрепить напрямую или через модем.
3. Включи вентилятор Create с источником лавы. Сам SmelterOS не управляет вращением/нагревом.
4. Настрой в AE2 **processing pattern** с входом, выходом и Pattern Provider. Проверь, что обратно в Pattern Provider **физически можно вставлять** результат; это зависит от AE2 и сборки. Если нельзя — настрой отдельный выходной сундук и AE2 Import Bus.
5. Сначала положи **один тестовый предмет** в дубовый ящик. Убедись, что депо пустое. На мониторе нажми **START FEED**.

### Названия периферийных устройств

Первичная автоконфигурация подходит к ранее показанным устройствам:

| Назначение | Предпочтительное обнаружение | Резервное имя |
|---|---|---|
| Вход | Functional Storage | `left` |
| Депо | `create:depot` | `back` |
| Выход | `ae2:pattern_provider` | `ae2:pattern_provider_0` |
| Экран | `monitor` | `right` |

Для фиксированных имён после первого запуска введи `edit /smelteros/data/config` и замени `"auto"` на реальные имена (например `"create:depot_0"` или `"left"`), затем перезагрузи компьютер. Файл конфигурации записан как сериализованная Lua-таблица, **без `return`**, например:

```lua
{
  enabled = false,
  input = "left",
  depot = "back",
  output = "ae2:pattern_provider_0",
  monitor = "right",
  batch_limit = 64,
  poll_seconds = 0.5,
  timeout_seconds = 300,
  estimate_seconds = 15,
  monitor_scale = 0.5,
}
```

> Если `pushItems()` выдаёт ошибку, убедись, что **все три** инвентаря доступны как периферии одной проводной сети и модемы активированы. Имя удалённого инвентаря может отличаться от `back`/`left`.

## Как работает

1. Состояние `IDLE`: ждёт ресурс во входном ящике и разрешение `START FEED`.
2. `LOADING`: **до** перемещения сохраняет журнал и отпечаток `getItemDetail()` исходного предмета.
3. `PROCESSING`: проверяет предмет на депо каждые `0.5` секунды; как только меняется **ID** (`name`), хеш **NBT** (`nbt`) или другое доступное метаданное, переход к выгрузке.
4. `UNLOADING`: пытается перенести изменённый предмет в настроенный выход. Если выход отказал, показывает `FAULT` и **не выбрасывает предмет на землю**. После исправления нажми `RETRY FAULT`.
5. `FAULT`: останавливает новые перемещения, оставляет предмет на месте. `PAUSE FEED` запрещает *новые* партии, но активная партия может завершиться.

**Ограничения:**

- Наблюдается только то, что показывает CC: Tweaked. В некоторых версиях/модах поле `nbt` отсутствует или скрывает изменения. **100%-го обнаружения любого NBT гарантировать нельзя.**
- Create не отдаёт через этот интерфейс достоверный процент работы ветродуйки. Прогресс-бар — лишь **оценка по времени** (параметр `estimate_seconds`); состояние партии решается **по реальному изменению предмета**.
- Завод рассчитан на **один тип входа за партию** и **один занятый слот депо**. Многоингредиентные рецепты и результат, который падает в мир, не поддерживаются.
- Вставка из CC:T в Pattern Provider **зависит от возможностей AE2/интеграции** и пока не проверена. Выход можно переключить на сундук с AE2 Import Bus.
- Если уже лежащий на депо предмет не имеет сохранённого исходного отпечатка, контроллер потребует очистить его вручную. Это защищает от ошибочной выгрузки при восстановлении.
- В журнале предусмотрено восстановление после перезагрузки, но нестандартные сценарии с частичным переносом и одновременным изменением вручную требуют проверки в игре.

## Управление

- `START FEED` / `PAUSE FEED`: разрешить/запретить *новые* партии; настройка сохраняется при перезагрузках.
- `RETRY FAULT`: после ремонта подключения или выхода повторить остановленную операцию.
- `Ctrl+T` в терминале: остановить программу. `reboot`: перезапустить компьютер.
- Для проверки имён периферии: `lua` → `print(textutils.serialize(peripheral.getNames()))` или `peripherals` в оболочке.

## Файлы на компьютере

```text
/startup.lua                  Автозагрузка
/smelteros/boot.lua           Загрузочный экран
/smelteros/main.lua           Главный цикл
/smelteros/core.lua           Движок состояния и проверки изменений
/smelteros/devices.lua        Поиск устройств
/smelteros/storage.lua        Журнал и конфигурация
/smelteros/ui.lua             Экран 4×2 + сенсорные кнопки
/smelteros/config.default.lua Значения по умолчанию
/smelteros/data/config        Настройки, переживают обновления
/smelteros/data/state         Журнал обработки, переживает обновления
```
